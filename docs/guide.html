Operator Guide

SEO & GEO Page Optimizer

A brand-agnostic, human-in-the-loop pipeline that optimizes one page at a time for classic search and AI answers (AI Overviews, ChatGPT, Perplexity, Gemini, Claude). This guide shows how to set it up, run both tracks, and what every helper script does.

What it is

You give it a page slug (to improve a live page) or a topic (to write a new one). It pulls the page's Search Console performance and strategy into one brief, researches competitors and the live AI Overview, and produces a self-contained HTML file. For existing pages the output carries color-coded review markers (green = add, red = remove) plus a changes summary; new pages ship clean.

Everything brand-specific lives in one file, config.json. Point it at any site by editing that file. Nothing is hard-coded.

The one principle behind it all: make the answer to each likely question extractable in one self-contained passage, backed by a verifiable, current cited fact, with unambiguous entities and a clean heading path to it. That serves classic SEO, AI Overviews, answer engines, and generative assistants at once.

1 · Set up

Configure the brand

Open config.json and set your brand_name, domain, base_url, the URL segments (info_path / blog_path), money_page_pattern, course_keyword_map, and the country_slugs list (geo pages that must never be linked to).

Install & try it without your own data

pip install -r requirements.txt

# copy the committed sample data to run the tooling immediately
cp data/scorecard.example.json data/scorecard.json
cp data/audit.example.json   data/audit.json
python optimizer/lookup.py product-certification

Build real data from your exports

When you have Google Search Console + page-inventory .xlsx exports, regenerate the data files (the input contract is documented at the top of build_scorecard.py):

python build_scorecard.py   # -> data/scorecard.json + data/audit.json

2 · Run a page

Two tracks, one page at a time. In Claude Code, use the slash commands; both wait for your approval at the plan step before building.

/optimize-page product-certification      # improve an existing live page
/new-page "how to measure training roi"   # write a brand-new page

Optimize-existing pipeline

1 Intelligencelookup.py + check_bots.py; scrape the live page
2 Slug reviewkeep or 301-redirect to a better slug
3 Scopeoptimize / pivot / merge / reposition
4 Auditscore against the 50-point checklist
5 ResearchSERP + AI Overview, gaps, PAA, keywords
6 Plancannibal.py + interlink.py; get approval
7 Buildgreen/red markers, AIO opener, FAQ+JSON-LD
8 QA + saveqa_check.py, meta_audit.py, ledger.py
9 Verify (~30d)verify.py: citations + GSC deltas

New-page track skips the scrape/audit, treats cannibalization as make-or-break, and ships clean HTML (no diff markers); QA runs with --new.

4 · The QA gate

qa_check.py is the pass/fail gate every page clears before saving. Exit code 0 means all hard checks passed. It enforces the mechanical rules so nothing ships that breaks one; judgment checks (flow, factual accuracy, competitor-gap value) still happen by hand.

python optimizer/qa_check.py "final output/<slug>-green.html" --words 3200 --keyword "product certification"
python optimizer/qa_check.py "final output/<slug>.html" --words 1800 --new --keyword "training roi"

Auto-enforced AUTO

  • Zero em dashes, en dashes, and -- sentence breaks; American English only.
  • Link budget by word count, max 1 link per paragraph, no CTA anchor text, no country/city links.
  • Brand named at most once in the reader body.
  • Meta title ≤ 60 chars; meta description 140–160 (target ~150–155).
  • One H1, answer-first opening paragraph (30+ words), and a valid heading hierarchy (no skipped levels).
  • Every <img> has descriptive alt text and a non-generic filename.
  • FAQ HTML matches the FAQPage JSON-LD count; every JSON-LD block parses; a present Article is complete.
  • A current-year freshness date (dateModified or a visible "last updated") is present.
  • No pre-2024 statistics (a year before 2024 sitting next to a stat signal).
  • With --keyword: primary keyword in H1, first 100 words, and conclusion, and not stuffed (1–6 uses).
  • Optimize mode: a .changes-summary table is present. New mode: no leftover diff markers.

Do by hand MANUAL

The 50-point re-score, article flow & readability, whether cited sources really say what is quoted (spot-check 3–4), whether new sections fill a real gap vs padding, and cannibalization judgment.

5 · Input & output

Input

  • Setup: config.json + GSC/inventory .xlsx exports (or the committed *.example.json).
  • Optimize: a page slug + optional GSC keywords. The pipeline scrapes the live page itself.
  • New: a topic / working title + optional primary keyword + optional GSC keywords.
  • Human approval at the plan gate.
  • Post-publish: your observations (per-engine cited y/n, CTR/position deltas) → verify.py.

Output

  • Optimize: final output/{slug}-green.html — review copy with green/red markers, publishing fields, AIO opener, FAQ + JSON-LD, and a changes-summary table.
  • New: final output/{slug}.html — clean, publish-ready HTML.
  • A report: before/after metrics, QA scorecard, 50-point delta, 3 meta options, AI-Overview angle.
  • State: content_ledger.json, verification_log.json, regenerated scorecard/audit.

In: one config + your data + a slug or topic per page.  Out: a QA-gated, review-ready HTML file per page, plus the tracking data that decides what to do next.
